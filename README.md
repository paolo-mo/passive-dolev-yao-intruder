# jpcap2ser — Reconstructing Passive Dolev–Yao Intruders from PCAP

This repository accompanies the paper **"Global Surveillance Under the Lens: Reconstructing Passive Dolev–Yao Intruders"** by Paolo Modesti (Teesside University). It contains the toolchain, experimental scripts, and data used to reconstruct passive Dolev–Yao intruder executions from captured network traffic, validate them against an AnBx protocol specification, and evaluate the approach over 121 protocols.

The pipeline takes a PCAP capture produced under a passive man-in-the-middle configuration, together with an AnBx specification and deployment metadata, and produces executable Java code that reconstructs the captured trace. The generated passive intruder reads per-step serialised objects, performs compiler-derived defensive checks (well-formedness, equality, inversion, seen), and scores candidate reconstructions. The intruder never modifies traffic; it observes, reconstructs, and validates.

## The reconstruction pipeline

The pipeline follows the five stages described in the paper (Section 3):

| Stage | Description | Script / tool |
| ---: | --- | --- |
| 1 | Generate JavaDocker code (`anbxc -out:JavaDocker -jdockerpcap`) | `run_test.py` |
| 2 | Run Docker and capture PCAP (`run_javadocker`) | `run_test.py` |
| 3 | Extract TCP streams and metadata (`jpcap2ser.py` → `outparse.py`) | `jpcap2ser.py`, `outparse.py` |
| 4 | Pair connections, group sessions, and enumerate candidate arrangements | `sessionbuild.py` |
| 5 | **Pass A:** ObjCheck per candidate and snapshot STEP files. **Pass B:** Java generation and passive intruder per candidate × session; score and select the winner. | `run_test.py` |

The passive intruder is generated by the AnBx compiler (`anbxc -out:Java -objcheck`) and reads per-step files named `{Protocol}_{session}_STEP_{n}.ser`. The scoring tuple is `(n_clean_sessions, -total_failed_checks, total_checks)`; higher is better. The winning candidate's reconstruction is copied to the working path, and its per-stage return codes replace the aggregate codes recorded in the CSV.

## Prerequisites

The toolchain was evaluated on Windows 11 with:

- Python 3.14.3
- AnBx compiler 2026.09 (GHC 9.10.3)
- TShark (Wireshark) 4.4.8
- Java OpenJDK 21.0.12
- Docker Desktop 4.89
- Apache Ant 1.10.17
- Bouncy Castle 1.85.2 (optional; only for BC provider runs)

The AnBx compiler and runtime library are distributed separately; see https://paolo.science/anbx/.

## Configuration

Edit jpcap2ser.cfg to match your environment. Key settings:

```ini
[DEFAULT]
# -------------------- Paths --------------------
# Directory where the AnBx compiler writes generated Java code
BASE_PATH       = <path-to-java-generation-directory>

# Root of the AnBx/OFMC distribution (contains anbx-dist/)
BASEDIR         = <path-to-anbx-distribution>

# Directory containing jpcap2ser.py, outparse.py, sessionbuild.py
TOOLBASEDIR     = <path-to-tool-directory>

# Directory containing the .AnBx protocol specifications
PROT_FOLDER     = <path-to-protocol-specifications>

# Log and output directories
LOG_FOLDER      = <path-to-log-directory>
OUTPUT_FOLDER   = <path-to-output-directory>

# -------------------- Tools --------------------
# Path to the Ant executable
ANT_CMD         = <path-to-ant-executable>

# Path to the TShark executable
TSHARK_CMD      = <path-to-tshark-executable>

# Path to the SerializationDumper JAR
SERDUMP_JAR_FILE = <path-to-serialization-dumper-jar>

# -------------------- Protocol filtering --------------------
# Comma-separated list of protocols excluded from `run_test.py --all`
EXCLUDE_PROTOCOLS = BIP70,Bullet_Channel,...,TLS_pw
```

Relative paths are resolved relative to the config-file directory. EXCLUDE_PROTOCOLS is honoured by run_test.py --all unless --include-excluded is passed.
## Usage

### 1. Run the full pipeline

Single protocol:

```bash
python run_test.py Carlsen --sessions 1 --provider JDK --csv all_protocols_timing.csv
```

All protocols (excluding `EXCLUDE_PROTOCOLS`):

```bash
python run_test.py --all --sessions 2 --provider JDK --csv all_protocols_timing-jdk-2s.csv
```

A comma-separated list:

```bash
python run_test.py --protocols Carlsen,WooLam,NSPK --sessions 3 --provider BC --csv timing.csv
```

Options of interest:

- `--sessions N` — number of parallel sessions (default: 1)
- `--provider {BC,JDK}` — cryptographic provider (default: JDK)
- `--debug` — print stage stdout/stderr and protocol specification
- `--strict-sessions` — abort on ambiguous session grouping
- `--log-suffix SUFFIX` — distinguish log files across runs
- `--no-log`, `--no-csv` — disable log/CSV output

The CSV receives one row per protocol with per-stage times (*_t), return codes (*_rc), and the sessions / provider metadata fields.

The batch helpers run_exp.cmd, run_mutations.cmd, and run_recovery.cmd reproduce the campaign configurations used in the paper.
### 2. Parse logs into accuracy statistics

```bash
python parse-logs.py log/ --csv protocol_stats.csv
```

Accepts a log file or a directory of .txt/.log files. Emits one row per (protocol, candidate) and prints a summary covering success rates, object recovery, check counts, and the parallel-capable / sequential-only split (based on the All sessions completed markers in the runtime logs).
### 3. Analyse timing data

```bash
python analyse-timing.py --csv all_protocols_timing-jdk-1s.csv
```

Options: --provider {BC,JDK,all}, --debug.

Produces summary statistics, normalised breakdowns, Docker overhead, scalability analysis, correlation analysis, and extreme protocols.
### 4. Mutation experiment

```bash
python mutate_and_verify.py --protocols Carlsen,WooLam --sessions 1 --verbose --csv mutations_n1.csv
```

Requires a successful pipeline run for the target protocols, so that the winner snapshot directory `{BASE_PATH}/<protocol>/<Protocol>_step_snapshots/c<winner>/` exists. Mutations:

- `deletion` — remove one STEP file
- `duplication` — copy one STEP file over another in the same session
- `cross_session` — copy a STEP file from one session over the same step in another (`N ≥ 2`)

A mutation is attributed to the intruder if it reports check FAILED! or runagents exits non-zero, and to completeness if it executes fewer checks than the unmutated baseline. The two attributions are mutually exclusive in the reported CSV. See Section 4.6.3 of the paper for the full discussion of what is and is not detected.
### 5. Discrimination experiment (role-mapping mismatch)

```bash
python discrimination.py --root discrimination-experiment/carlsen
```

Runs a 2×2 matrix: capture (ref/swap) × check instantiation (ref/swap). The diagonal cells pass; the off-diagonal cells fail at equality checks on role identities. The Carlsen captures, both .properties files, and the four intruder logs are retained in discrimination-experiment/carlsen/ for inspection.
### 6. Hand-written implementation experiments

See handwritten/Readme.md. These demonstrate that Stage 3 (extraction) is independent of the AnBx compiler and runtime library. Hand-written extractors (ExtractCheck_*.java) replace ObjCheck for these captures. The three experiments cover:

- `Tutorial_06` — AnBxJ 5-message exchange (both endpoints on localhost)
- `Tutorial_07` — pure-JDK 5-message exchange, no AnBxJ on the classpath
- `handwritten_hybrid_rsa_aes` — hybrid RSA+AES, exercises interface-typed public keys and raw `byte[]` arrays
